# 💳 v1.1 — In-App Purchase для Pro на iOS (план)

Мета: повернути покупку Pro в iOS-збірку **легально**, через Apple StoreKit, за **330 ₴/міс** (≈ +33% до 249₴ — покриває комісію Apple 15–30%). Android може лишитися на LiqPay або теж перейти на Google Play Billing — нижче обидва варіанти.

## Чому RevenueCat
Capacitor сам не дає StoreKit/Play Billing. Замість писати дві нативні інтеграції — беремо **RevenueCat** (безкоштовно до $2.5k/міс виручки): один SDK на обидві платформи, готові вебхуки, керування цінами з дашборда, і — головне — він стає містком до нашого Supabase.

## Архітектура (лягає на наявну модель)
Джерело істини вже є: `tutor_workspace_settings.subscription_status` (`free|trial|active|past_due|cancelled`), а `isPro` рахується з нього. IAP просто стає ще одним джерелом, що виставляє `active`.

```
Користувач (iOS) → купує в застосунку → Apple StoreKit
        → RevenueCat фіксує покупку (entitlement "pro")
        → RevenueCat webhook → наша edge-функція revenuecat-webhook
        → UPDATE tutor_workspace_settings SET subscription_status='active' / 'cancelled'
        → клієнт уже вміє показувати Pro
```

- [ ] Створити Auto-Renewable Subscription, product id `pro_monthly_330`, ціна — український тариф ≈330₴ (вибрати з тарифної сітки Apple).
- [ ] (Опц.) річний `pro_yearly`.
- [ ] Заповнити localization + скріншот рев'ю.

### 2. RevenueCat
- [ ] Проєкт → додати App Store app (+ Google Play, якщо мігруємо Android).
- [ ] Entitlement `pro` → прив'язати обидва product id.
- [ ] Offerings: один `default` з monthly/yearly пакетами.
- [ ] Скопіювати public SDK key (iOS) і webhook authorization header.

### 3. Клієнт (Capacitor)
- [ ] `npm i @revenuecat/purchases-capacitor`
- [ ] Ініціалізація лише в нативі:
  ```ts
  import { Purchases } from "@revenuecat/purchases-capacitor";
  import { isNativeApp, isIosApp } from "@/lib/platform";
  if (isNativeApp()) {
    await Purchases.configure({ apiKey: RC_KEY, appUserID: supabaseUserId });
  }
  ```
  (appUserID = Supabase user.id — так вебхук знатиме, кому виставити Pro.)
- [ ] У SubscriptionPage: де зараз `iosApp` ховає LiqPay — натомість показати StoreKit-кнопку:
  ```ts
  const offerings = await Purchases.getOfferings();
  await Purchases.purchasePackage({ aPackage: offerings.current.monthly });
  ```
  Плюс обов'язкова кнопка **«Відновити покупки»** (`Purchases.restorePurchases()`) — вимога Apple.
- [ ] Прибрати приховування цін на iOS після того, як IAP працює (ціни знову можна показувати — вони тепер Apple-ціни).

### 4. Edge-функція `revenuecat-webhook`
- [ ] Перевірка `Authorization` header == секрет RevenueCat.
- [ ] На події `INITIAL_PURCHASE|RENEWAL|UNCANCELLATION` → `subscription_status='active'`; на `CANCELLATION|EXPIRATION` → `cancelled`; на `BILLING_ISSUE` → `past_due`.
- [ ] Знаходити репетитора за `app_user_id` (= Supabase user.id). Патерн авторизації — як у наявних функцій (service role).
- [ ] Деплой + прописати URL у RevenueCat dashboard.

### 5. Тестування
- [ ] App Store Sandbox tester → купити, відновити, скасувати; перевірити, що `subscription_status` міняється і Pro вмикається/гасне.
- [ ] Перевірити синхронізацію на двох пристроях під одним акаунтом.
