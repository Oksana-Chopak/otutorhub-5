# UI-MERGE-PLAN — злиття створювачів (виконати ПЕРШИМ після Publish-смоуку)

## Чому не «зараз»: реліз-безпека
Обидві форми вже уніфіковані ПОЛЯМИ (SubjectSelect, DateTimeField, токени) —
розбіжність лишилась у МОЖЛИВОСТЯХ, не у вигляді. Зливати наживо флоу, яким
власниця щодня створює уроки, без ручного прогону — неприйнятний ризик.

## Ціль: один <LessonCreateDialog /> для ВСІХ ролей
База = теперішня інлайн-форма Розкладу (найбагатша). Кроки:
1. Механічне винесення інлайн-форми Розкладу в src/components/LessonCreateDialog.tsx
   (пропси: open, onOpenChange, defaults {tutorId?, studentId?, groupId?, startsAt?},
   role-режим виводиться зсередини як зараз). Поведінка 1:1, лише переїзд.
2. Додати в неї єдину відсутню можливість QLD: створення ГРУПОВОГО уроку
   (перемикач «Учень / Група» + вибір групи; payload як у QLD).
3. Перемкнути всі точки входу: Dashboard hub-tutor FAB, Dashboard indep,
   Dashboard manager (+), Schedule «+», Groups «запланувати» → LessonCreateDialog.
4. Видалити QuickLessonDialog повністю; розтяжку №11 звузити до
   {LessonCreateDialog.tsx}; №8-скан незмінний.
5. Смоук по ролях: менеджер / hub-репетитор / незалежний / учень (pending).

## Учень-створення (менеджерське) — другий етап
People-форма лишається канонічною для менеджера (звʼязка «репетитор+ставки»).
Ціль: спільний <StudentUpsertDialog /> з пропом tutorPicker для менеджера;
QuickAddStudentDialog вливається туди ж. Кроки аналогічні (перенос 1:1 →
розширення → перемкнути входи → видалити стару → звузити розтяжку).
